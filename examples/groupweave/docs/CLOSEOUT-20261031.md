## M6 · 六个反向案例

M5 完成后才执行。应用使用合成 Telegram 用户/两个群、有效合成签名和明确角色
响应；原生检查使用本项目拥有的两个真实 Docker/OpenShell 沙箱。没有真实秘密
进入测试输入，没有模型请求、Telegram 消息或共享服务扫描。

| 案例 | 实际输入/操作 | 预期与观察 | 结果 |
| --- | --- | --- | --- |
| 1. 跨群读取 | A 登录会话提交 B 的群、任务、文件与提案 ID；本群成员猜他人的私有任务 ID | 原生模式 API 返回 404，响应不含另一作用域正文；合法本人仍可领取原文件并读历史 | PASS · 应用 API |
| 2. 伪造身份/越权 | 伪造 `x-role`/`x-actor-id`、任务 JSON 身份字段、文字声称平台管理员；成员改规则、群管理员安装插件 | 伪造 JSON 拒绝400，成员配置拒绝403，非平台安装拒绝403且安装器调用数0；真实平台身份也不自动获得群数据 | PASS · 应用签名登录/角色接缝 |
| 3. 文件/路径 | 附件名为遍历或绝对宿主 canary 路径；下载目标符号链接指向私有目录外；替换文件内容/沙箱ID | 附件名仅作展示/分类，获取只用获准 Telegram 文件 ID/path；未读 canary。Bridge 仅下载固定 result.md，拒绝链接/错内容/错身份，授权撤回不释放正文或文件 | PASS · 媒体处理器/原生 adapter 本地 HTTP/Bridge 真实临时文件接缝 |
| 4. 提示注入/凭据 | 恶意网页指令要求提权/读密钥，模型返回越权 JSON，执行器异常含合成秘密；真实沙箱放恶意 Skill 后直接运行宽 shell 文件探针 | 配置候选警告且不能启用、权限不变、原始异常不回传。两个沙箱均打不开所测十类宿主/凭据/socket路径，宿主环境 canary 未继承；工作区文字没有增加挂载或工具 | PASS · 应用校验与真实原生容器路径边界 |

| 6. 后台投递归属 | A 猜 B 提醒 ID 做删除/暂停/修改，伪造 raw chat 目标，删除 B feed；随后关 A 的 RSS/提醒 | B 的记录保留；正常 A/B 投递作对照后，关闭 A 只抑制 A 的后续原生 RSS/提醒，B 继续。A 关闭后仍能删除自己订阅 | PASS · pinned RSS emitter/schedule/SQLite，本地发送记录口 |

## 必须保留的限制

- 应用权限和后台检查使用合成身份/角色与本地发送口；没有本轮逐项重测 Telegram
  远程角色服务和所有发送组合。真实 TG 正常功能证据仍由此前日期记录证明。
- Bridge 符号链接检查使用 fake native CLI 与真实临时文件。没有独立验证上游远端
  symlink 传输的全部语义；真实原生探针支撑的是宿主路径/挂载不可见与新工作区。
- 没有调用模型，因而没有验证模型会遵守恶意文字。这里验证的是恶意数据无法
  扩大应用权限，以及在能运行 shell 的沙箱内也打不开所测宿主路径。
- 原生探针不需要网络，本次网络策略为空；**没有验证生产出站网络隔离**。
  Sandbox JWT 限制属于 pinned 源码/既有原生契约，没有本轮提取或重放 live JWT。
- 可信 Koishi 插件共用应用进程和数据权限；平台持有 mTLS 证书是控制面权限，
  不等于每租户证书授权。Docker 共用宿主内核，不承诺通用逃逸防护或没有未知漏洞。
- RSS/提醒停用不撤回已进入发送流程的消息。已授权历史、备份和 WAL 不因沙箱
  清理而被抹除；OS 管理员和可信平台代码仍属于受信边界。
