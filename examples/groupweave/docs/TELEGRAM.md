## 明确启动模式

默认 `APP_MODE=preview`，仅 loopback 发布，合成身份/群不映射任何真实群；即使
存在 Token 也不初始化/轮询。真实模式须明确设置 `APP_MODE=telegram`、
`TELEGRAM_BOT_TOKEN` 和独立 `TELEGRAM_ADMIN_IDS`，并完成 getMe 核验。
平台 IDs 只提供全局维护资格，不提供群管理权。

Telegram adapter 没有真实 binding、Token 或平台 ID 时停止；init/options 本身
不等于业务验收；getMe 成功后为 ready/connected，原生 polling onStart 成功后
才为 polling。两种状态都不证明真实群收发已验收。没有 webhook/runner/
自动重试/额外队列。关闭会断开授权、取消 init、等待 polling 与实际 middleware
结束；迟到的 init/onStart/成员查询不能重写新生命周期的状态。

## 群注册与指令

Bot 必须是群/超级群的管理员，才能可靠核验其他用户当前身份。

| 入口 | 使用者 | 行为 |
| --- | --- | --- |
| `/register` | 当前本群 admin | 创建本群独立配置空间；重新核验，不注册其他群 |
| `/start`、`/help`（私聊） | 普通个人 | 固定接入引导；不列群、不读群、不接受群 ID 授权；私聊业务/管理尚未接入 |
| `/start`、`/help`（群内） | 当前成员 | 本群实际可用功能、匹配本群响应方式的用法；当前群管理员另看到管理入口 |
| `/plugins` | 当前成员 | 只显示平台已启用、真实可用且本群已配置的功能；不枚举全局插件、其他群配置或任务内容 |
| `/settings` | 当前本群 admin | 本群版本、当前可用功能和配置参数，以及受支持的 `/rules` 修改示例；只读，不授予平台能力 |
| `/rules 只使用命令，使用英文，去重` | 当前本群 admin | 共用规则解析、版本与提案，InlineKeyboard 预览确认 |
| 确认按钮 | 提案创建者仍为本群 admin | callback绑定群/创建者/实际提案，CAS启用，不用data授权 |
| `/links 文本` | 当前成员，command模式 | 本群参数进入真实 DSH 链接函数，group受众 |
| `/links@BotUsername 文本` 或明确 @Bot 的纯链接 | 当前成员，mention模式 | 显式目标触发，外来Bot命令不会执行 |
| `/echo 文本` | 当前成员 | 官方 Koishi 插件回显当前文本；0 次 LLM 调用；命令式内容不成为选项 |
| `/digest 文本` | 当前成员 | 原生确认后摘要；1 次模型尝试、无工具 |
| `/brief 文本` | 当前成员 | 原生确认后 AI → 链接插件 → AI；2 次模型、1 次成功工具；本群链接依赖持续有效 |
| `/ask 文本` | 当前成员 | 原生确认后群助手；无工具为 1 模型/0 工具，链接工具为 2 模型/1 工具；无任意工具或历史访问 |
| `/scan 文本` | 当前成员 | 复用 antiad 纯预测；0 次 LLM 调用、实际本地分类器；只给判定建议，不自动处罚 |
| `/cancel`、处理中的取消按钮 | 当前成员 | 只取消本人在当前群的活跃任务，不接受目标人/群/任意任务 ID |
| `new_chat_members` | 当前群的可信 Telegram 事件 | 已启用 welcome 时运行 Koishi 明文模板；成员显示名仅为输入，触发者仍需当前成员资格 |

群内链接结果会公开给本群，不提供群内“私人”结果假象。面板可选择仅自己或本群。
代码/AI 命令可以在命令后提交当前文本，也可明确回复一条本群文本后发命令。
回复对象只提供输入，其作者不授予发起者群权。AI 必须走下面的本人确认；
不自动读取群历史。mention 模式业务命令须带实际 `@BotUsername`。纯链接 @
运行代码；含目标描述的 @ 优先进入已开放助手的确认入口，缺助手时按实际
能力进入摘要或功能指引，含链接且无助手时仍可走链接代码。

### 三种使用路径

- **群成员**：在群里用 `/help` 或 `/plugins` 发现本群功能；按照返回的
  已开放的 `/links`、`/echo`、`/scan` 或 AI 命令，用正确命令目标/明确 @
  提交当前文本；AI 每次确认。群内返回公开
  给本群，面板的“仅自己”任务是单独入口。成员帮助不展示管理员规则编辑入口。
- **群主/群管理员**：先 `/register`，用 `/settings` 查看本群设置，再用
  `/rules 只使用命令，中文，开启链接整理，去重并排序，最多10条` 预览并确认。
  规则解析目前只接受列出的有限表达，不是通用自然语言理解；未知要求会阻止
  启用。修改作用于 update 所在群，文本里写其他群 ID 不改变目标。
- **平台管理员**：维护平台插件的全局开关、已接入能力与维护工具；群内
  `/settings` 仍要求其实际是当前群管理员。需要新能力先由平台维护者接入，
  群管理员随后才能选择；群内命令不能安装插件、接入凭据或更改全局能力。

发现命令也会重新查询当前成员身份；平台停用、本群关闭功能后，`/plugins`
不再把该功能宣传为可用。未注册群给出 `/register` 指引，不自动注册。
`/settings` 返回的群运行参数会发到当前群，不包含任务输入/结果、平台凭据、
内部审计或其他群信息。管理员身份在发送前再次核验。真实启动配置显式
启用原生 `setMyCommands`；菜单注册失败只记录固定错误码，不破坏已核验的
初始化与业务入口。菜单是指引，本群实际可用范围仍由 `/plugins` 和请求检查决定。

`responseMode` 控制自动触发，不影响群注册/管理命令。`language` 控制原生链接
输出与TG提示；无注册群使用默认中文。超长TG输出采用固定长度上限提示截断，
关闭链接预览，保留当前 forum thread。链接不会被fetch。

## 每次 AI 确认与欢迎事件

`/digest`、`/brief`、`/ask` 先发送 Telegram 原生 InlineKeyboard，明确说明
只处理本次选中输入、会发送给已配置的第三方模型、群内结果公开。模型只能在
发起者确认后运行；面板的确认也不成为 Telegram 的永久同意。

签名绑定功能、本人、当前群、源消息 ID、原 update ID、精确输入和触发方式，
有效期 5 分钟。确认消息回复到实际选中的文本；回调重读该回复并验签，
修改原文、冒用他人、跨群、伪造、缺失回复、过期、重复同意均拒绝。
服务只保留最多 512 条已消耗签名和过期时间，不复制输入；未过期记录满额时
拒绝新增消费，不驱逐记录放开重放。进程/adapter 重建换密钥，旧按钮失效；
持久任务幂等和投递键仍负责业务不重跑。处理中反馈含本人本群取消按钮，
撤权后按钮也不授权限；取消未知副作用与上游计费仍需按实际证据核对。

欢迎由 `new_chat_members` 触发，只使用当前事件的普通新成员显示名和当前群
配置，不读取聊天历史。模板只一遍替换 `{name}` 和 `{group}`，最终为普通文本；
显示名、模板或群标题中的消息组件、命令与表达式不会执行。Bot 自己及其他
Bot 加入不生成欢迎；发送前重查当前群启用/平台状态和触发者权限。

`/scan` 只分析当前明确文本；缺少批准模型、Python 依赖或真实初始化证据时
能力保持不可用/blocked，不用规则文本假装分类器完成，也不转 AI。
原机器人的自动验证、举报、申诉、处罚、全局样本与训练尚未接入。

## 身份与隔离

群来自可信 update.chat，个人来自普通 from；sender_chat匿名、频道、转发来源
与私人聊天不授群权。平台 IDs 不替代实际群管理员资格。`restricted` 只有
is_member=true 可作为成员。每次操作查询当前 getChat/getChatMember 与 Bot 权限；
API失败拒绝，数据库成员表只是观察，撤权删观察。

真实群ID为 `tg:<负安全整数>`，个人为 `tg-user:<正安全整数>`；合成preview隔离。
配置、提案、任务与投递绑定实际群和creator。群迁移仅接受 Telegram service
字段，并核验目标Bot群权限；拒绝冲突目标，不从文本选ID，不合并陌生群。
迁移固化pending/claimed为未知；旧scope返回不能覆盖新记录或继续投递。

执行后与实际发送前再次核验成员、当前群功能、平台启停、受众及使用过的代码依赖，收缩权限则
withheld。最后核验与Telegram发送不是原子事务，远端已接收的数据无法撤回。
同进程可信代码不是恶意插件隔离；尚未开放群历史、附件或插件/AI的通用
凭据访问能力。已支持的 Bot Token 与 DeepSeek 应用专用 Key 属于部署/宿主
配置，不成为群用户或模型可选择的工具参数。

## 重复、失败与限流

update_id/message_id形成本群本人的重复保护键；Store预留先于执行，同键返回
原记录，不自动重跑。业务结果发送先持久claim再调用sendMessage；sent、unknown、
withheld不重开，响应丢失也不重发。失败且无output的任务仅发送一次固定安全
能力提示，不透传底层错误或用户输入；blocked/撤权结果不交付。
这提供防自动重放策略，不提供Telegram与SQLite跨系统exactly-once。

官方ratelimiter默认每人3/2秒、每群10/2秒，在业务入口前丢弃超额update。
服务仍共用总活跃2/每群1的fail-fast容量限制，没有Redis与后台队列。
AI 失败或取消没有业务重试/模型切换；欢迎、Echo 和链接任务不调用 LLM。

## Mini App 面板

前端复用 `@tma.js/bridge.retrieveRawInitData()`，不解析/重组签名原文；后端用
`@tma.js/init-data-node`作者SDK校验Token签名、5分钟时间、未来时间、重复字段
和个人ID。它不是Telegram官方维护SDK。签名只建立个人会话，群权另查。

PUBLIC_ORIGIN须为精确无路径HTTPS origin，启用Secure Cookie、同源Origin/Host
与CSRF；不信任X-Forwarded-*授身份。普通浏览器不能选择真实个人；演示入口
在真实模式关闭。配置Mini App和现成HTTPS反向代理属于部署工作，未执行。

群内 `/settings` 只提示从已配置的 Mini App 入口打开面板，没有构造普通 HTTPS
“登录”链接或群内 `web_app` 按钮。Telegram 的 `initData` 必须来自真实 Mini App
启动并在服务端校验；身份签名也不能替代本群权限检查。入口配置与具体 launch
方式以 [Telegram Mini Apps 官方文档](https://core.telegram.org/bots/webapps)
为准；命令可见范围只影响菜单展示，权限仍在实际请求中验证。

## 受控真实验收顺序

2026-10-13 的受控真实运行已覆盖清单中的启动、身份核验、polling，以及一个
真实用户/测试群的注册、帮助、规则确认和 Echo。以下清单中其他身份、撤权、
跨群、Mini App、模型与恢复场景仍需分别验收；通过这次窄范围运行不能推导这些
场景通过。

1. 用应用专用Token与独立平台ID启动真实模式；Bot作为一个受控群管理员。
2. /register后测试成员使用、群admin预览/确认、其他群与成员修改拒绝。
3. 测mention/command与语言、重复update/按钮、未知发送与重启不重放。
4. 测用户退群/降权、Bot移出/降权、平台停用、迁群和迟到执行结果。
5. 配HTTPS与Mini App，测真实登录、注销/跨标签、移动界面与受众。
6. 明确启用AI后单独测本人/本群/回复文本确认、过期/重放、真实用量、
   处理中撤权/取消，以及摘要、助手和链接说明质量。
7. 用批准的只读模型单独验证 `/scan`、缺模型拒绝、两群阈值/词表、实际分类
   成本；欢迎模板与群话题也须真实验收。
8. 服务器受控负载与point-in-time恢复另验，不能从离线样本推导稳定承载数。

默认容器只发布本机4318。真实模式可使用compose.telegram.yaml显式override，
仍复用现成HTTPS入口；不自动公开端口、不读取现有用户密钥、不部署deployment host。


反广告使用同一服务的可选容器构建：默认镜像无需 Python，明确使用
[compose.antiad.yaml](../compose.antiad.yaml) 才安装锁定依赖并挂载部署管理员
批准的只读基准模型。模型路径、解释器和文件不接受群用户/AI 选择或上传；
joblib/pickle 可执行代码，属于部署信任边界。单次固定短进程，不按群部署容器。
来源和接口见 [antiad 适配说明](../integrations/antiad/README.md)。它与同进程
Koishi 插件都不提供任意恶意代码沙箱，完整模块与后续业务见 [MODULES](MODULES.md)。
