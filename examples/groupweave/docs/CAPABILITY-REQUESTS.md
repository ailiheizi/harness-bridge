# 群能力申请

群管理员可以把想要的功能提交给平台维护者，在同一个页面跟进进度。无需配置外部工单系统，不调用模型。

## 群管理员怎么用

1. 从 Telegram 已配置的管理 Mini App 进入网页，选择自己管理的群。
2. 打开侧栏「能力申请」，或在「功能配置」点击「向平台申请」。
3. 填写想要的功能和使用方式，例如谁使用、输入什么、希望得到什么结果。可以提供公开插件名称；不要填写 Token、密码或私人聊天记录。
4. 点击「提交能力申请」。申请保存在服务端，平台管理员可以在「群需求」看到；刷新页面仍保留。
5. 在申请记录查看状态与平台回复。仍待处理或处理中的申请可以撤回，撤回前会再次显示要撤回的标题。

本群当前管理员共同可见和管理本群申请；普通成员没有该管理入口。其他群不能读取记录。原管理员降权后不再可用。

## 平台维护者怎么用

打开侧栏「群需求」，按状态筛选申请，点「处理申请」，填写说明并保存：

| 状态 | 含义 |
| --- | --- |
| 待处理 | 已记录，尚未接手 |
| 处理中 | 平台已接手，说明当前进度 |
| 已提供 | 平台已经提供能力，在回复中说明实际使用命令、入口和必要配置 |
| 暂不提供 | 说明暂不支持的原因或替代方法 |
| 已撤回 | 本群管理员取消需求 |

平台只能看到主动提交的申请内容和群标识，不能通过此入口读取群配置、对话和任务。回复是普通文本。每次保存都检查版本；若被另一管理员更新，应刷新后重新处理。

「已提供」记录平台的人工交付结论。它不自动安装 npm 包、启用全局能力或修改本群配置。插件维护仍走既有平台入口，本群启用仍须原来的预览与确认。已结案记录不能再改；需要调整可重新提交。

## 范围与保存

- 标题最多 120 字，用途和每次回复最多 2000 字；不附加群聊天历史。
- 同群相同标题、相同用途的未结案申请会返回已有记录。
- 每群最多 20 项未结案申请，平台总计最多 2000 项未结案。保留每群最近 50 项结案记录；页面每批显示最多 50 项，支持翻页。
- 申请随应用 SQLite 保存、备份和群升级迁移。数据库升级到 schema 5；恢复旧 schema 4 备份时沿既有迁移流程升级。
- 当前通过页面刷新查看进度，没有自动 Telegram/邮件提醒、附件、讨论串或自动执行。

## 接入实现

复用 Fastify 会话、Origin/CSRF、当前 Telegram 群管理员校验及 Store。群端 `/api/groups/:id/capability-requests` 负责提交、查询、撤回；平台端 `/api/platform/capability-requests` 负责显式需求处理。身份、群、版本和权限由宿主判断。申请内容只是数据，不会成为安装命令、Skill 或授权。

这是完整 Bot 的宿主业务功能，未向 Harness Bridge 增加运行时、队列、插件市场或鉴权代理。
