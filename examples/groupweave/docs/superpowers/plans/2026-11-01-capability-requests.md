# 群能力申请交付计划

> **For agentic workers:** Use superpowers:executing-plans. 用户已授权连续补齐里程碑并由实施者决策；不重复请求流程批准。检查遵守 ADR-039。

**Goal:** 群管理员在现有网页提交能力用途，平台维护者处理并回复，群管理员能看到进度和撤回未完成申请。

**Architecture:** 使用当前 GroupWeave Store、Fastify 会话/CSRF/当前群权限和角色工作区。申请是宿主业务记录，不触发安装、授权、模型或消息发送；代码仍归完整 Bot 案例，不扩张 Bridge。

**Tech Stack:** 现有 node:sqlite、Fastify、React、Lucide；无新依赖。

## 设计与决策

原待办明确缺少能力申请。直接增加本群申请和平台处理最符合现有三角色职责；外部工单会增加账户/接入要求，自动安装或 AI 审批会改变平台维护权限，均不采用。本轮决策由实施者按既有自主授权作出。

- Web 群管理员入口「能力申请」，平台入口「群需求」；普通成员无申请记录权限，平台只能看到显式提交的用途，不能因此读取群配置/任务。
- 标题 1–120 字、用途 1–2000 字；提示勿填写密钥/聊天记录。群和提交人来自会话，不接受客户端角色、状态或目标覆盖。
- 状态 submitted/reviewing/delivered/declined/cancelled。平台可接手或给出完成/暂不提供结论；所有平台更新需 1–2000 字说明。群管理员可撤回未结案请求。结案不可再改。
- 操作使用当前版本号，冲突必须刷新；同一群相同标题与用途的未结案请求去重。
- 每群至多 20 个未结案，保留最近 50 个结案记录；全局至多 2000 个未结案。列表分批 50 条，平台可按状态筛选。业务记录随已有 DB 备份；schema 4→5 原地迁移，已有资料保留。
- 重启持久化、群升级迁移、当前角色变化需要正确处理；无新定时器/通知系统。用户通过刷新查看进度。
- 「已提供」是平台说明交付入口的人工结论，不等于自动开启本群插件；现有功能配置预览/确认照常。
