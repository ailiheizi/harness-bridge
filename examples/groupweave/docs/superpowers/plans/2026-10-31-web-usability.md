# Web 工作区与功能发现实施计划

> 执行方式：superpowers:executing-plans；本轮在已有 codex/deployment-completion 分支继续，保留现有依赖与部署。用户已授权自主决策与推进，不再次做设计问答。

**Goal:** 让平台维护者、群管理员与成员能找到已交付工具并完成自己的常用操作。

**Architecture:** 保留 React/Vite、Lucide 与现有授权 API。目录仅展示命令和依赖，不直接执行工具；运行和修改继续使用既有宿主入口。

**Tech Stack:** React 19、TypeScript、现有 CSS、Lucide。

## 设计与取舍

选择整理现有工作区，而非引入另一后台框架或把平台 Koishi Console 暴露给群成员。参考 AstrBot 插件的搜索/分类/状态，Koishi 的插件配置与运行状态分工。设计由执行者根据已授权需求决定，不声称用户逐项批准视觉方案。

- 导航分群工作区、平台管理；当前群、身份和规则版本可见。
- 总览改为日常操作入口；现有原生工具进入可搜索命令目录。
- 工具卡明确“本群允许”不等于“服务已部署”；群管理员专属操作明确标注。
- 平台插件维护分依赖/安装/配置；JSON 仅留给平台高级配置，不在成员流程展示。
- 插件与记录搜索筛选；手机使用可折叠菜单，字号、触控区域和对比度提高。

## 约束与检查重点

不加依赖、后端、权限或执行协议；保留 request-scope 作用域失效与确认流程。
不再逐项测试已复用上游；低影响样式不写镜像实现的测试。
只用独立本地合成预览检查 UI，不发模型请求，不动现有服务器或群配置。
特别检查：切换群/身份不残留私有结果；成员看不到管理入口；搜索空态可恢复；部署依赖不能宣称已就绪；小屏表单与导航可用。
