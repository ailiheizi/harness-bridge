## 群管理员：Web 可以直接找回规则并回滚

之前 Web 启用规则后清空预览，却要求用户提供提案 ID 才能回滚。现在预览及
启用提示显示 ID，规则页直接列出本人本群仍保留的已生效提案；刷新页面也可
选择历史记录，生成原有回滚预览，再次确认后才应用。

历史复用 proposals 表和现有每群保留上限（默认50条）。新增查询先核对当前群
管理员身份，再按当前创建者及群过滤；其他管理员的草稿、其他群记录不会返回。
身份/群/规则版本切换后卸载旧组件，迟到响应不写回新页面。没有新状态库或浏览器
持久 ID 清单，回滚仍经原版本比较和确认。原因记录在 [ADR-043](DECISIONS.md)。

检查：

- API 回归先复现历史路由404，修复后通过。同群另一管理员、成员、其他群、
  降权及伪造查询操作者不能读取本人以外记录；数据库重开后能找回原提案。
- 本地浏览器实际操作：上限20→7、确认到v2、刷新页面、从历史选择回滚预览、
  确认到v3恢复20。此处使用独立临时预览身份，没有修改真实群规则。
- 更新已经部署到既有 Bot；健康、Telegram/执行器连接及原生持证 CLI 检查通过。
  schema4、全部原群配置、会话和插件记录保持，未恢复数据库，未改其他业务服务。
  这是目标修复部署证据，与下面的默认镜像构建证据分开。

## 平台部署者：可选模型配置进入 Compose

原生 Compose 现在透传现有 `SANDBOX_AI_MODEL_PROFILES`；可选
`compose.koishi.profiles.yaml` 将受保护目录只读挂到固定容器路径，缺配置直接失败，
不加 overlay 时保留空默认值。继续复用 `loadSandboxProfiles`，不添加路由或自动切换。

manifest 不保存密钥，模块/私有 provider 文件由平台维护；附加 Sub2API binding
使用独立端口和可写状态目录。权限、容器绝对路径、包装现有 factory 的完整例子及
启动命令见 [使用指南](M1-M4-USAGE.md#会话任务与模型)。真实 Compose 解析验证透传、
只读挂载、禁止自动创建缺失路径、无 overlay 默认值及缺变量拒绝。

本轮没有配置或调用第二个线上模型；现有线上仍只有 default。不能将配置接线
通过说成所有模型均可用。
