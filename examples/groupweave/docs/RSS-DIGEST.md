# 预装的每日订阅摘要

本群管理员可以直接启用一个已有组合：**原生 RSS 新通知 → 现有 DSH 摘要 → 本群投递**。
轮询仍由 `koishi-plugin-rss` 管理，触发/重启恢复仍由 `koishi-plugin-schedule` 管理。
有限计划、待汇总通知、去重摘要和尝试次数存于同一个原生 Koishi 数据库。
不是新的工作流引擎、任务队列或自建调度服务。

## 怎么使用

先由平台配置 AI，开放摘要能力；本群启用 `digest`、`rss`、`schedule`，
并用现有 `/rss <feed-url>` 添加来源。然后在群主对话发送：

```text
/rssdigest 每天09:00
```

也可用 `/rssdigest daily 09:00`。默认有效 7 天、最多 7 次尝试；
可显式指定 `/rssdigest 每天09:00 14天 10次`，期限/次数上限均为 31。

机器人先显示来源、时区/时间、模型、输出范围、第三方处理、期限和尝试上限。
预览不启用计划。由同一管理员在同一群 10 分钟内发送返回的
`/rssdigest confirm <ID>` 才启用。创建者每次运行仍须是当前群管理员。

- `/rssdigest status` 查看计划和待汇总数。
- `/rssdigest run` 立即处理本日新条目，使用同一额度/授权和去重，不绕过按日上限。
- `/rssdigest stop` 或 `pause` 停止并清理本计划的日程与待汇总内容；原 RSS 订阅保留。
- 恢复或改变时间先重新预览/确认；不把一次文本确认当作无限自动运行授权。

每群一个计划；新计划替换旧计划。新计划从确认后的新通知开始收集。
原来逐条 RSS 通知仍照常推送，摘要是额外的每日汇总，不静默改变既有订阅行为。

## 边界与费用

- 来源固定为确认时本群全部已订阅源，1–20 个；来源集合改变后须重确认。
- 仅输入上游 RSS 已准备投递给本群的标题/链接通知，不抓网页全文，不读群历史。
- 最多缓存20条、每条350字节、保留最近128个去重hash；超限计数如实加入摘要输入。
  长标题/链接可能被截断，不承诺完整保留所有条目或正文。
- 无新条目不调用模型；每天最多尝试一次、每次最多一个摘要模型请求。
  期限/尝试上限、当天尝试和入库先于模型执行，重启不自动重放收费。
- 确认的模型ID固定使用现有可信profile。切换模型、权限变化、到期或次数用尽需重确认。
- 失败、取消、发送状态未知均不自动重试。尝试额度可能已消耗而实际模型调用为0；
  真正计量见任务记录，不把次数上限说成金额预算。
- 停止会请求取消本次执行，并阻止迟到结果开始投递；已经开始的发送不能撤回。
- 平台/本群禁用、创建者降权、来源变化都不得继续新模型处理；模型文本不能改目标。
- 自动摘要输出对当前群公开。后台任务仍经宿主权限、容量、计量、取消和投递检查。

## 部署与验证

不新增环境变量或npm包；使用现有原生入口与AI配置。原生数据库增加
`groupweave_rss_digest` 具体业务表，Store仍为schema4。备份/迁移保留整个现有数据卷和两个数据库；
不要只恢复计划表或旧计费记录后自动重放。

本轮聚焦验证覆盖：原生RSS投递scope采集、原生schedule保存与其存储事件执行、
预览/确认归属、无新条目零调用、同日重启不重复、来源变化/失权拒绝、
停止后迟到结果及旧鉴权响应不能误停新计划。模型和外部收件证据另列，不由这些测试推断。
