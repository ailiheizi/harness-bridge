# 原生问答与文件

2026-10-26，适用于 `npm run start:koishi`。固定文件功能不需要模型。
本说明对应 AIL-17、AIL-24、AIL-29、AIL-94 的已实现部分，未完成部分列在末尾。

## 群问答与摘要

平台管理员先配置 `ENABLE_AI=1` 和 `SANDBOX_AI_BINDING_MODULE`，后者必须是
已有 Docker/OpenShell/DSH 部署的受保护 `.mjs` 绑定。它包含原生执行路径、
固定镜像和模型预算/用量回执接入；单独提供 API key 不会建立这个执行环境。
路径及部署约束见 [Sandbox AI](SANDBOX-AI.md)。缺少绑定会阻止启用 AI 的
宿主启动；默认 `ENABLE_AI=0` 时其他功能正常可用。

模型配置不会自动授予群权限。平台在现有管理面板启用「群助手」和「智能摘要」，
本群管理员再按下列步骤选择本群功能：

```text
/rules 开启群助手，开启摘要
/applyrules <预览返回的提案ID>
/ask 用一个简单例子解释递归
/digest <要摘要的文字>
```

也可回复同群的一条文字或带文字说明的消息，然后发送不带正文的 `/ask` 或
`/digest`；明确回复选择的内容可来自其他群员或机器人消息。命令有正文时使用
命令正文；不会自动合并未选中的引用内容。
输入最多 8000 UTF-8 字节，不读取群历史，图片说明只作为文字处理。

机器人先提示第三方模型处理，发起者在五分钟内点击确认才执行。按钮绑定本人、
本群和这段输入；已使用按钮不能再次执行。同群其他人的点击不代替发起者确认。
运行时提示处理中，可用 `/cancel` 取消本人的本群任务。模型不可用、超时或
未取得执行证据时明确提示失败，不返回模拟答案，也不会自动改用其他执行入口。

群规则选择「仅 @ 时响应」时，使用 `/ask@机器人用户名 <文字>`，或直接
`@机器人用户名 <问题>`。直接 @ 走群助手，仍需本人确认。普通命令模式不会
监听所有聊天内容触发 AI。

摘要复用 `audited/group-summary/SKILL.md`，问答使用
`audited/single-turn-assistant/SKILL.md`。两者固定一次模型请求、零工具调用，
通过同一个现有 Bridge/Docker 路径执行。问答可用模型自身知识回答；不会宣称
查过网页、操作过设备或读取过群历史。长回复逐段引用原消息，保留完整文字；
每段再次核验权限，发送回执未知时停止剩余投递，不自动重发。

## 私聊问答与摘要

同一模型部署绑定和平台功能开关启用后，私聊可直接发文字、`/ask <问题>`、
`/digest <文本>`，或回复本会话文字后使用命令。普通文字先给本人确认按钮，
确认后才发送给第三方模型；附件说明不会自行触发问答。`/cancel` 取消本人当前
私聊中仍在执行的任务；执行完成后的分段投递不属于可取消的执行任务。

## 预装翻译与链接说明

群助手已启用时，群内和本人私聊可使用 `/translate 英语 需要翻译的文字`。
目标语言为一个参数（如 `英语`、`English`、`日本語`）；多个词用引号，
例如 `/translate "Traditional Chinese" Hello, world!`。文本直接写在命令中，
保留正文内部换行；首版不提供只引用消息的翻译。先经本人确认，再通过普通
`audited/text-translation/SKILL.md` 执行一次模型请求。它复用群助手授权，
不新增平台开关或翻译工作流配置。源文本不会获得工具权限。

群内 `/brief <包含链接的文字>` 先运行现有链接整理代码，再将原文及真实整理
结果交给 Docker 内的一次模型请求说明。也可引用同群文字后发送 `/brief`。
平台和群必须同时开放「链接整理」与「链接整理与说明」；私聊不开放该组合。

```text
/rules 开启链接整理，开启链接整理与说明
/applyrules <预览返回的提案ID>
/brief 这两个项目供比较：https://example.com/a https://example.com/b
```

排序、去重和条数使用本群现有设置，不调用模型决定固定步骤。模型只根据提供的
文字和 URL 作解释，**不会访问网页**。该路径使用独立的普通
`audited/docker-link-brief/SKILL.md`，记录一次模型请求及一次宿主代码调用，
模型侧工具调用为零。旧入口的 `audited/link-brief/SKILL.md` 保持原有绑定。
没有链接、模型失败、权限撤销或取消均不报告组合成功。取消仍使用 `/cancel`。

## 私人作用域

每人使用独立 `tg-dm:<用户ID>`，任务和投递只归本人；不创建伪群，不读取或列出
该用户加入的群。首批私人配置固定为中文、摘要与问答，仍受平台启用状态限制。
多轮聊天历史与个人设置界面未实现。已有存储升级为 schema 3，见
[存储说明](STORAGE.md)。

## 文件与媒体入口

已注册群内的当前成员和私聊本人可用：

| 操作 | 用法 | 实际结果 |
| --- | --- | --- |
| 查看附件 | 回复附件后 `/fileinfo` | 显示类型、文件名和已知大小；不下载正文 |
| 读取文本 | 回复 `.txt` / `.md` 后 `/readfile` | 通过官方 adapter 下载并严格解码 UTF-8，分段回复 |
| 生成文件 | `/savefile <文字>` | 官方 adapter 上传真实 TXT 文件，Telegram 接收后可下载 |

可识别图片、视频、文档、音频和语音。读取只支持扩展名为 `.txt` / `.md` 的
UTF-8 文本，最多 64 KiB；不支持的类型、过大或无法解码会给出提示。
媒体类型识别不代表 OCR、语音识别已经实现。

附件来自本次消息或同会话引用消息，命令不接受任意下载 URL、本地路径。
文字及文件回复引用本次请求；内容作为普通文字发送。结果文件在内存中生成，
交给 Telegram 官方编码器上传，没有把临时磁盘路径作为下载链接。
发送回执未知时停止，不承诺已经收到。群话题入口暂不支持。

## 视频转 GIF

平台设置 `ENABLE_MEDIA=1` 后启动原生入口，可使用：

| 输入 | 操作 |
| --- | --- |
| 上传 | `/v2g`，在 20 秒内由本人在同一会话上传视频 |
| 引用 | 回复同一会话的视频消息，发送 `/v2g` |
| 视频链接 | `/v2g https://.../video.mp4`，需要可直接访问的视频资源 |

复用 `koishi-plugin-video-to-gif@1.2.2` 的命令与转换逻辑，以及
`koishi-plugin-ffmpeg@1.1.0` 的 FFmpeg 服务。默认最多 10 MiB、60 秒，输出
15 fps、320 px 宽的 GIF。转换由代码执行，不调用模型。私聊限本人，群内需要
已登记群的当前成员；此批由平台环境开关统一开放，尚无逐群媒体参数界面。

`/cancelv2g` 只取消当前机器人、当前会话和当前用户正在等待视频或处理的
`/v2g`。取消会撤销上传等待、通过 HTTP AbortSignal 停止视频下载、终止正在运行
的 FFmpeg 进程并清理本任务临时文件。单个任务从开始起最多运行 60 秒。若 GIF
已经交给 Telegram 开始上传，取消或 60 秒期限会停止等待上传结果，但不能撤回
已经发出的 Telegram 请求；该 GIF 仍可能到达。

本机需已有 FFmpeg 和 ffprobe，默认从 PATH 查找，可分别用 `FFMPEG_PATH`、
`FFPROBE_PATH` 指定。Compose 会
在 `ENABLE_MEDIA=1` 时构建含系统 FFmpeg 的应用镜像；不启用则不增加该镜像依赖。
启用而缺少程序时启动明确失败。没有安装新的沙箱或调度器，固定媒体插件运行
在应用容器，AI 仍走既有独立 Docker 执行路径。

本地小补丁兼容 Telegram 默认 data URI，修正上游等待上传误收其他用户视频、
定时器和失败临时文件清理，并增加上述单会话取消与 60 秒任务上限。20 秒为
等待上传期限。HTTP 视频仍缓冲下载后检查大小，不承诺下载内存硬上限。任意大小、
格式及并发不在本批已验证范围。

## 常用视频与音频预设

同样通过 `ENABLE_MEDIA=1` 启用，回复同会话视频、音频或媒体文档后使用：

| 命令 | 实际操作 |
| --- | --- |
| `/convert mp4` | 转为 H.264 视频和 AAC 音频的 MP4 |
| `/convert mp3` | 从有音轨的文件提取 128 kbps MP3 |
| `/convert m4a` | 提取 128 kbps AAC，封装为 M4A |
| `/convert small` | 输出宽度至多 480 px、较低质量的 MP4，并显示实际大小；不保证一定比源文件小 |
| `/clip 5 10` | 从第 5 秒起取 10 秒视频，输出 MP4；参数为起点和时长 |
| `/mediainfo` | ffprobe 返回实际容器、时长、视频编码/尺寸、音频编码/声道及文件大小 |
| `/cancelmedia` | 取消本人在当前会话运行的新媒体预设；不取消上游 `/v2g` |

当前消息附带媒体和同会话引用均可；这些新命令不下载任意 URL，不处理群话题。
首版使用 Telegram 远程文件 API，本地 Bot API 文件模式会提示暂不支持。
使用 FFmpeg/ffprobe 固定参数，没有为每次请求生成脚本，不消耗模型调用。
输入最多 10 MiB、60 秒，输出最多 25 MiB；每人每会话一个、全局两个，忙时提示
稍后再试，不排队。每项处理期限 60 秒，转换结束才通过官方 adapter 上传真实
文件，临时目录随任务清理。无音轨、无效格式、越界截取和程序失败都有错误提示。
下载请求接入任务取消/期限，转换后再用 ffprobe 核对输出，拒绝明显被大小上限
截断的文件。下载前检查 Telegram 报告大小、下载后检查实际字节；这仍是缓冲
下载，不宣称流式内存硬上限。取消等待下载/进程结束和清理后反馈，清理失败会
明确提示管理员处理。正式收件仍以 Telegram 回执为准。

  文件上传 FormData，以及现有 Store/actions 与 Bridge 合约。模型和 Telegram

  动画上传内容；只有 Telegram 网络回复由替身提供，不等于真实 TG 收到文件。
- MP4、MP3/M4A、截取、较小视频预设与 ffprobe 已接入本地实际处理。
  [图片/PDF/Markdown](NATIVE-IMAGES.md)已补齐本地处理，

  沙箱文件产物回传仍未交付。
- 原生入口的真实 Telegram 文件与媒体收发见[应用验收第八批](ACCEPTANCE-20261022-NATIVE.md)：
